# 数据质检规范：如何区分「数据特殊性」与「解析 Bug」

> 本文件记录本项目在数据清洗阶段建立的方法论。
> 后续扩展关卡页、敌人页、道具页时，沿用同一套流程。

## 一、为什么需要这套规范

解析器跑完，完整度报告会显示「精英化材料 95.2%」。
这个数字本身**没有意义**，因为剩下 4.8% 可能是三种完全不同的情况：

| 类型 | 例子 | 该怎么处理 |
|---|---|---|
| A. 数据固有特性 | 1 星小车没有技能 | **不修**，写进豁免规则 |
| B. 源数据未填写 | wiki 编辑者还没填模组 | **不修**，记录并接受 |
| C. 解析器未覆盖 | 页面用了另一代模板 | **必须修** |

如果把 A 当 bug 去改，会越改越错；
如果把 C 当 A 放过，Agent 会答错。

**人工逐个排查不可持续**——每改一次解析器就要重查一遍。
所以判断过程必须自动化。

## 二、三层判定法（已实现于 `scripts/05_diagnose.py`）

```
字段缺失
   │
   ├─ 第 1 层：命中领域豁免规则？  ── 是 ─→ 【A】数据固有特性，豁免
   │      （规则写在 src/parser/profile.py）
   │
   ├─ 第 2 层：回原始 wikitext 查，页面里根本没有该模板？
   │                                    ── 是 ─→ 【B】源数据未填写，豁免
   │
   └─ 第 3 层：页面里有模板，但没解析出来 ──→ 【C】解析器待修（真 bug）
```

只有第 3 层需要人介入。诊断脚本会直接打印待修页面的名单和原因，
并列出「疑似未识别的新模板变体」作为补充线索。

### 关键设计：领域知识必须写成可执行规则

第 1 层的规则不是拍脑袋，而是**游戏机制的形式化**：

```python
{
    "field": "精英化材料",
    "when":  lambda r: r.get("星级", 0) <= 2,
    "reason": "1~2 星干员无法精英化",
}
```

这样每次跑脚本都会自动应用，而不是靠人记着。

## 三、已确认的领域规则（干员数据）

### 干员子集划分

| 类别 | 判定依据 | 数量 | 养成体系 |
|---|---|---|---|
| 常规 | `干员序号 > 0` | 432 | 标准：精英化材料、技能升级材料、模组 |
| 特勤 | 序号 > 0 且含 `{{特勤干员}}` | 2 | 靠集成战略任务解锁，**无材料消耗** |
| 特殊模式 | `干员序号 = -1` | 29 | 无（卫戍协议 / 集成战略专属） |

另有**异格/升变干员**（`{{异格干员/升变}}`，如 阿米娅→近卫/医疗）：
由剧情升变解锁，**不需要精英化材料**。

### 各星级的合理形态（用于交叉校验）

| 星级 | 应有技能数 | 能否精英化 | 有无模组 |
|---|---|---|---|
| 1~2 星 | 0（支援小车） | 否 | 无 |
| 3 星 | 1 | 是 | 无 |
| 4~5 星 | 2 | 是 | 有 |
| 6 星 | 3 | 是 | 有 |

### 已知的 wiki 模板变体

同一语义在不同年代用了不同模板，解析器**必须全部支持**：

| 语义 | 模板演变 |
|---|---|
| 天赋 | `天赋列表`（`第一天赋N=`）→ `天赋列表2` → `天赋列表3`（`天赋N=`） |
| 技能 | `技能` → `技能2` |

> 教训：泥岩页面**同时**使用了 `技能2`（一、二技能）和 `技能`（三技能）。
> 用「取 A or 取 B」的写法会漏掉一类，必须**按出现顺序合并**。

## 四、两个易踩的坑

**坑 1：完整度分母错了。**
把「本来就不该有该字段」的干员算进分母，会把数据固有特性误报成缺失。
分母 = 全部干员 − 命中豁免规则的干员。

**坑 2：字段存在 ≠ 字段有值。**
`天赋: []`（空列表）在完整度统计里算「缺失」，但看起来像解析器跑通了。
所以除了完整度，还必须看**条目总数**（如精英化材料 3185 条）。

## 五、扩展新页面类型时的检查清单

- [ ] 先跑勘探脚本，确认标识模板（`次/页 ≈ 1` 的才是标识）
- [ ] 解析器支持该语义的**所有**模板变体，按出现顺序合并
- [ ] 在 `profile.py` 补充该类型的豁免规则和模板映射
- [ ] 跑 `05_diagnose.py`，确认【C】类为 0
- [ ] 抽查 2~3 个已知样本做人工验证（自动化发现不了「数值偏一位」）
